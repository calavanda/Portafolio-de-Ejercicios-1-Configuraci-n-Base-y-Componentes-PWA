5. Explicación Téorica del Ejercicio 4

1

Evento install y caches.open()

Durante la instalación del Service Worker, se ejecuta caches.open('app-shell-v1') para abrir o crear una bóveda de almacenamiento estático.

2

Almacenamiento del App Shell con cache.addAll()

Se guardan de forma atómica los archivos estáticos indispensables (HTML, CSS, JS e imágenes base) en la memoria caché.

3

Intercepción fetch & Estrategia Cache-First

Al realizar peticiones, caches.match(event.request) busca el recurso. Si existe, se entrega al instante sin hacer uso de la red.

Código Fuente del Service Worker (`sw.js`)

// 1. Nombre de la memoria caché y lista del App Shell const CACHE_NAME = 'app-shell-v1'; const APP_SHELL_ASSETS = [ './', './index.html', './styles.css', './app.js', './manifest.json', './images/app_shell_banner.jpg' ]; // 2. Evento Install: Crear caché y guardar App Shell self.addEventListener('install', (event) => { event.waitUntil( caches.open(CACHE_NAME).then((cache) => { return cache.addAll(APP_SHELL_ASSETS); }) ); }); // 3. Evento Fetch: Interceptar con Estrategia Cache-First self.addEventListener('fetch', (event) => { event.respondWith( caches.match(event.request).then((cachedResponse) => { // Si está en la Cache API, devolver respuesta precachada if (cachedResponse) { return cachedResponse; } // Si no está en caché, consultar a la Red return fetch(event.request); }) ); });
